# MusicNerdDocs — Agent Guide

The documentation site for the [Music Nerd API](https://github.com/xdjs/MusicNerdAPI): guides, an API reference generated from OpenAPI, a **Try it** playground on every endpoint, and machine-readable copies for AI tools (`/llms.txt`, `/llms-full.txt`, `/raw/<page>.md`, and Markdown on `Accept: text/markdown`). A self-hosted alternative to Mintlify, ported from Recoup's marketing `/docs` engine. Next.js 16 on Vercel; every PR gets a preview.

Issues and trackers live in [xdjs/MusicNerdWeb](https://github.com/xdjs/MusicNerdWeb/issues). Link PRs by full ref (`xdjs/MusicNerdWeb#1365`).

## Docs first

An endpoint is documented here **before** it is built in MusicNerdAPI:

1. **Docs PR** here: the endpoint's OpenAPI operation and its reference page.
2. **API PR** in MusicNerdAPI: code that meets the page, test first.
3. **Client PR** in whichever app uses it.

Document only what the code will actually do. When behaviour changes, update the page in the same change.

## Layout

| Path | What lives there |
| --- | --- |
| `content/source/docs.json` | Navigation: tabs, groups, page order (Mintlify's format) |
| `content/source/*.mdx` | Guide pages |
| `content/source/api-reference/openapi/<domain>.json` | One OpenAPI 3.1 document per domain: every summary, description, parameter, schema and example |
| `content/source/api-reference/<group>/<page>.mdx` | Reference pages: **frontmatter only** (`title`, `openapi: 'METHOD /path'`) |
| `content/{manifest,navigation,inventory}.json` | Generated by `pnpm docs:build`; committed |
| `app/`, `components/docs/`, `lib/` | The renderer, playground and machine-readable routes |

## Add or change an endpoint

1. Add the operation to its domain's OpenAPI file. Give it `security`: `[]` for public, or a scheme from `components.securitySchemes`. Endpoints are **public unless they return private data or change something**.
2. Add a frontmatter-only page under `content/source/api-reference/<group>/` and list it in `docs.json`.
3. `pnpm docs:build`, then commit the source and the regenerated JSON together. A test fails on drift.

MDX allows only `Card`, `CardGroup`, `CodeGroup`, `Info`, `Note`, `Tip` and `Warning`; imports and expressions are rejected at build.

## Commands

```bash
pnpm install
pnpm docs:build   # regenerate content/*.json from content/source
pnpm test         # vitest
pnpm type-check
pnpm lint:check
pnpm build
```

CI runs tests, types, lint and the build on every PR.

## Git

- Branch from `main`, open a **draft** PR to `main`, mark it ready only when its developer says it's good to merge, squash merge. Code branches are `<contributor>/<slug>`; docs-only branches may be `docs/<slug>`. Conventional commits.
- Verify every PR on its Vercel preview (deployment protection is off, so a browser or Chrome DevTools can open it directly) and post what you checked on the PR.
- **The repo is public.** No secrets, tokens, emails or database refs. Example IDs are staging fixtures.
