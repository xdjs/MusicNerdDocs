# Agent requirements: current state and proposed changes

Assessment date: October 5, 2026. Requested by Pete after reviewing side research. Owners remain [MusicNerdWeb#1424](https://github.com/xdjs/MusicNerdWeb/issues/1424) (shared API knowledge) and [#1422](https://github.com/xdjs/MusicNerdWeb/issues/1422) (interviewer/evaluation). Delivery stays **social ingestion → shared API tools → Web interviewer integration**.

This is a code/evidence assessment and scope proposal. No tool endpoint, schema, model, live prompt or interviewer behavior has changed as a result. “Experiment” below means the private API#19 CLI, not an active route. The adjacent [tool contract](artist-knowledge-tools.md) and [OpenAPI proposal](artist-knowledge.openapi.json) are drafts, not implemented operations. Proposed additions in this assessment have not yet been folded into a final endpoint schema.

## Proposed changes, before implementation expansion

### Phase 2 — #1424

1. **Make evidence resolution the contract.** Keep the proposed seven tools. Listing/search return stable source IDs and revision-bound original passages; expansion either returns that revision or explicitly reports changed/unavailable evidence. Generated summaries have no independent factual authority. Source-ranking order never supplies identity. Historical replay requires retained versions; hash-based change detection alone must not be sold as an archive.
2. **Add provenance distinctions to the draft schema.** Separate publisher/uploader metadata and their claimed title/description from evidence text. Preserve source type, original/repost relationship where established, and speaker/author/subject with explicit unknowns. Separate upload/publication, ingestion and event dates. An inferred event date or speaker identity needs an original supporting passage; do not automatically convert it into an established fact. This modifies the proposed evidence schema, not the tool count.
3. **Define a mandatory-memory read contract.** Latest saved answer plus its identity/revision, applicable corrections and active boundaries must be readable with explicit completeness and permission scope. A storage failure or incomplete constraint traversal cannot masquerade as “no constraints.” Older permitted history remains selectively retrievable. The caller's exact newest unsaved answer overrides an older database value without rewriting its meaning.
4. **Propose durable boundary records and ownership.** Persist exact boundary wording with its originating turn, artist/session scope, active/retracted state and applicable lifetime. The authenticated interview save flow records artist intent; avoid interpreting every skip or inferred discomfort as a permanent ban. API reads expose the records to all authorized consumers. Schema and write-path work must be specified alongside the schema-owning Web migration; no generic autonomous memory-write tool is implied.
5. **Instrument retrieval and source readiness.** Return known coverage, truncation and extraction failures; preserve originals. Record corpus revision, requested/opened passages and tool latency without publishing private text. Durable link ingestion and source-version retention stay visible as separate implementation decisions, rather than being hidden in a read-only endpoint claim.

### Phase 3 / evaluation — #1422

1. **Enforce preparation in the controller.** Every generation receives the latest exact answer, applicable corrections and active boundaries before optional retrieval. Preserve this packet through tool-loop pruning, retries and a fresh session. Do not rely on the model remembering to search for a constraint.
2. **Use retrieved context across the whole process.** Trace retrieval → original-context reading → angle selection → drafting → checking. Check facts in both the question and its rationale. Distinguish a documented relationship from an openly framed possibility; two separately supported facts do not establish their connection.
3. **Add actual session-persistence tests.** Save a response and scoped boundary through the authenticated flow, terminate the session, create a fresh one and verify exact restoration, correction precedence and no repeated question. Include paraphrased repetition under a new question key, retracted boundaries, changed source versions and a database failure. Use explicitly synthetic test fixtures; never fabricate real artist answers.
4. **Freeze held-out cases before tuning.** Keep LATASHA, DUTCHYY and this video as regression/development cases. Propose a first held-out set of 12 independently annotated cases across at least four additional artists, plus paired supported/unsupported controls. Freeze sources, annotations and split before prompt/model changes, with repeated runs and identical evidence/budgets per comparison. This is a proposed initial scale, not a scheduled paid run or a statistical generalization claim.
5. **Make editorial acceptance independent.** Blind human review scores whether a question is specific, answerable, useful and follows what the artist said. Include supported questions the model wrongly rejects. A model's approval or a larger accepted-question count cannot satisfy release acceptance.

No graph database/framework, new model or replacement agent framework follows from these requirements. Choose retrieval/indexing machinery only after the evidence/latency comparison, not from a video's title.

## Proposed evaluation measurements

| Measure | What to count/check |
| --- | --- |
| Question usefulness | Blind human ratings and explicit accept/rewrite/reject decisions on delivered questions; reasons retained. |
| Unsupported premises | Asserted unsupported/contradicted claims in delivered questions **and rationales**, with source adjudication. |
| Missed qualifications | Annotated negations, exceptions, dates, speaker distinctions and conflicting passages omitted or strengthened. Attribute the failure to retrieval, reading, angle choice or drafting/checking. |
| Repetition | Exact-key and semantic repeats against prior asked/answered/skipped questions and public answers, including after a fresh session. A justified deeper follow-up is separately labelled. |
| False rejections | Independently judged supported/useful candidate questions rejected by the checker; retain positive controls, failed drafts and rejection reasons. |
| Retrieval/original reading | Required-passage recall, exact reference resolution, surrounding qualification coverage and explicit unreadable/missing evidence. A full-original control distinguishes retrieval misses from reasoning failures. |
| Latency | Tool and model stages plus full response p50/p95, cold/warm preparation and session-restoration time; label sample size. |
| Cost | Calls, provider token usage and priced cost by stage, including preparation, retries, repairs and failed attempts where usage is available. Unknown usage stays unknown. |

Report counts and denominators by failure class, not only one composite judge score. Compare the existing flow, shared retrieval pipeline and full-original control on the same eligible evidence. Prevent held-out labels or reference answers from entering prompts. Set release thresholds after the rubric/baseline is reviewed; critical regression cases must not silently accept invented premises or violate active boundaries. Small-case zero failures is not proof of universal reliability.

## Video verification: regression case, not architecture evidence

Pete supplied [the repost](https://www.youtube.com/watch?v=XdbpCM4yGyE). Its metadata names “Keep Graph,” while its English auto-captions at [39:30](https://www.youtube.com/watch?v=XdbpCM4yGyE&t=2370s) contain “everything keep attention.” The corresponding phrase appears in [Stanford Online's original recording at 20:30](https://www.youtube.com/watch?v=XfpMkf4rD6E&t=1230s). Surrounding captions concern removing recurrent components while retaining attention in the Transformer architecture. This does not establish a recommendation to use an agent graph framework or a graph database for Music Nerd.

Verification on October 5 compared downloaded caption tracks and metadata, not a full manual audio review. Auto-captions contain transcription errors in surrounding technical terms; do not elevate every caption word to a verified exact quotation. The short matching phrase is sufficient to identify this title/content mismatch, not to certify the entire repost.

Metadata distinguishes the repost's August 14, 2026 upload from Stanford Online's May 19, 2023 upload. Stanford's [Winter 2023 course schedule](https://web.stanford.edu/class/cs25/past/cs25-v2/) lists Karpathy's Introduction to Transformers on January 10. These are separate source facts: repost upload, original upload, scheduled lecture date. The schedule is not itself proof of an unscheduled recording date. Do not treat the 2026 repost as a new 2026 lecture.

Expected regression behavior: identify the passage's architectural scope, preserve original attribution/dates, reject the graph-framework inference and avoid using repeated repost descriptions as corroboration. This case is now known to the developers and must **not** be counted as held-out evaluation.
