# Durable API-backed interview sessions (draft)

Refs xdjs/MusicNerdWeb#1422 and #1424. Completes the fifth accepted slice after mandatory memory. Web owns question generation and presentation; API owns authenticated session, offer, exact-answer and finish persistence. Requires additive Web migration 0042, after 0041. No production rollout is implied.

All operations require `Authorization: Bearer <Privy access token>` from the current approved claimant or an administrator. They reauthorize inside the database transaction. Responses are flat, private/no-store. No caller-supplied account IDs. Errors use `{status:"error",code,error}`: 400 invalid input, 401 absent login, 403 wrong/revoked owner, 404 unavailable artist/session/offer, 409 stale state, 413 limits, 503 unavailable persistence. Reads never generate, scrape or write.

## Operations

- `GET /api/artist/{artistId}/interview/session`: latest durable session with saved questions, answers, immutable offer timestamps and stable original references, or `session:null`. Includes any unlinked legacy offered questions separately. This is a private read, not a generation trigger.
- `POST /api/artist/{artistId}/interview/session`: `{requestId:uuid}` explicitly starts a session. Repeating a request returns its original session, including after finish. One active session per artist. A different start request while a session is active returns 409; the caller reads and resumes it. Its sitting is allocated after previous session/answer sittings; original legacy offers must be answered/skipped first.
- `POST /api/artist/{artistId}/interview/session/{sessionId}/offer`: `{ordinal:1..3,memorySnapshotId:sha256,question:string,references:[...]}` saves one Web/agent-prepared question. The question is 10–500 exact characters and each of 1–3 references is either `{kind:"original",sourceId,revision,start,end,quote}` or `{kind:"answer",entryId,revision,start,end,quote}`. Quote length 8–1,600 characters; offsets are UTF-16. The API reopens permitted evidence, checks exact words/revisions, and restores mandatory memory under the artist lock before accepting its snapshot. It never treats a model's approval as editorial acceptance. No network/model calls inside this transaction. The next ordinal is accepted only after the earlier offer is answered/skipped. Concurrent requests for an existing ordinal return the persisted original instead of overwriting it. No generation starts on this endpoint.
- `POST /api/artist/{artistId}/interview/answers/{answerId}`: `{expectedRevision:sha256,answer:string|null}` saves the artist's exact text (1–8,000 characters with non-whitespace content) or an explicit skip. The previous revision protects against stale tabs; an identical repeat is idempotent. An offered row's question, sitting and offered timestamp never change. Historical answered rows cannot be edited through this endpoint. Pending legacy offers can be completed without generating replacements. A skip is not a topic instruction.
- `POST /api/artist/{artistId}/interview/session/{sessionId}/finish`: `{}` explicitly closes a sitting and records any still-open offer as skipped. A repeat is idempotent. Exact answers remain in shared history. The transaction queues the existing durable Lore refresh when answered material exists; no detached regeneration runs in Web. An API failure leaves the UI resumable.

A session returns id, sitting, state (`active` or `finished`), createdAt/closedAt, and up to three questions. A question returns id, questionKey, question, answer, state (`offered`, `answered`, `skipped`), revision, offeredAt, answerUpdatedAt, ordinal and immutable evidence references. Unlinked legacy offers use `ordinal:null` and no invented references. Their previous source keys/URLs remain intact in the existing answer table. An already-offered question remains visible after a correction; generating its successor requires a new complete mandatory-memory snapshot. Explicit boundaries use the separately documented boundary routes and their real questionKey.

Database tables are private `artist_interview_sessions` and `artist_interview_question_evidence`, linked to existing exact `artist_interview_answers`. Sessions can only be closed; stored question evidence is insert/read only for `mnweb`. API authorization, not role-wide RLS, isolates users. Legacy page-load generation is disabled in the new Web path. Start/Continue alone can generate; reload only restores a persisted offer. Web restores memory before generating, compares angles grounded in opened original passages, drafts and checks a single question, then submits it with its snapshot. An incomplete/oversized/stale memory read stops the operation explicitly.

Verification: real database constraints and app-role grants, two simultaneous starts/offers/answers, exact words and immutable offer timing, failed-memory/source revisions, revoked ownership, legacy offered rows, idempotent finish, fresh-client resume, skip versus boundary, no writes or model calls on reads. Full process evaluation uses production-derived LATASHÁ and Dutchyyy sources (including private PDFs through authenticated reads), retains rejected attempts, and reports editorial ratings separately from the model guard.
